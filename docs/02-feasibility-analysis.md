# 可行性分析

## 结论

**需求完全可行。** CS:GO / CS2 的本地配置文件以纯文本形式存放在 Steam `userdata` 目录下，迁移过程本质是“按 SteamID3 定位目录并复制文件”，没有加密、签名或在线验证等阻碍。

## 技术可行性

### 1. Steam 路径可自动发现

Steam 在 Windows 注册表中记录了安装路径：

- `HKEY_CURRENT_USER\Software\Valve\Steam` → `SteamPath`
- `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Valve\Steam` → `InstallPath`

读取注册表即可定位 Steam 根目录，进而得到 `userdata` 路径。失败时可回退到默认路径 `C:\Program Files (x86)\Steam`，并允许用户手动选择。

### 2. 账号目录结构固定

每个登录过的 Steam 账号在本地都有独立目录：

```text
userdata/
└── <SteamID3>/
    └── 730/
        └── local/
            └── cfg/
                ├── config.cfg
                ├── autoexec.cfg
                ├── video.txt
                └── ...
```

`730` 是 CS:GO / CS2 的 AppID，因此可以精确扫描。

### 3. 新账号目录可自动创建

如果目标账号从未运行过游戏，`730/local/cfg` 可能不存在。程序可以使用标准文件 API 递归创建目录，无需额外权限（通常用户对自己的 `userdata` 有写权限）。

### 4. 文件复制无技术障碍

`config.cfg`、`autoexec.cfg`、`video.txt` 均为普通文本文件，可直接复制。建议同时复制整个 `cfg` 目录，或允许用户勾选需要迁移的文件。

## 风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| Steam 路径读取失败 | 无法自动扫描 | 提供手动路径选择 |
| 目标账号正在运行游戏 | 文件被占用或覆盖 | 检测并提示先退出游戏 |
| 覆盖目标账号已有配置 | 数据丢失 | 应用前自动备份 |
| CS:GO 与 CS2 配置不兼容 | 部分指令失效 | 仅做文件迁移，不承诺指令兼容；提供文件预览 |
| Steam 云同步覆盖本地文件 | 迁移后被还原 | 提示用户注意云同步冲突，必要时选择“上传本地” |
| 多 Steam 安装目录 | 扫描不全 | 支持手动添加多个 Steam 库路径（后续迭代） |

## 实现难度评估

- **核心逻辑难度：低**。主要是注册表读取、目录遍历、文件复制。
- **UI 难度：低**。只需路径展示、账号列表、基准选择、应用按钮。
- **打包发布难度：低**。使用 .NET 可发布为单文件 exe。
- **总体工作量**：MVP 约 1~2 天即可完成。

## 建议

先实现一个最小可用版本（MVP）：自动扫描 → 选择基准账号 → 选择目标账号 → 一键复制并备份。后续再增加昵称识别、配置预览、多 Steam 路径支持等增强功能。
